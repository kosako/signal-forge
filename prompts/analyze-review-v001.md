# 確かめる観点
- title_ja・summary が本文と食い違っていないか。本文に無い事実・数字・固有名を足していないか、
  主語・結論・時制を取り違えていないか。本文が無いアイテム(extraction: failed)は、題名から
  言える範囲を超えていないか。
- relevance が、関心プロファイルに照らして妥当か(下のフィールド基準)。高すぎる・低すぎる点を直す。
  ↑基準に直撃する記事を低く付けていないか、↓基準だけの記事を高く付けていないかを特に見る。
- novelty が、配信済みタイトルと合っているか。
- negative・category・topic・reason・implication が、本文とプロファイルに合っているか。
- 直すのは、誤りがあるときか、判断が明らかにずれているときだけ。言い回しの好みや、どちらでも
  よい差では直さない。点は 10 未満の差なら直さない。

# 出力仕様
次の JSON スキーマに厳密に従う:
{{schema}}
- 渡した全アイテムについて、1 件ずつ結果を返す。
- verdict: 直す必要がなければ "ok" とし、analysis は null にする。直すなら "fixed" とし、
  analysis に直した後の分析を全フィールドそろえて返す。直さないフィールドは、最初の分析の値の
  ままにする。analysis.item_id はそのアイテムの id。
- note: fixed のとき、何をなぜ直したかを 1 文(80字以内)。ok のときは空文字。
フィールド基準(最初の分析と同じ):
- relevance: 関心プロファイル照合 0-100。↑基準に直撃なら 70 以上、
  ↓基準のみ該当なら 30 以下。判断がつかないものは 40-60。
- negative: ↓基準への該当ラベル(該当なしは空配列)。
- novelty: 配信済みタイトル・✅実例と同一トピックなら known、
  既知トピックの実質的な続報・進展なら update、それ以外は new。
- topic: 重複判定用の正規化トピックラベル(名詞句、15字以内)。
- title_ja: 日本語の見出し(60字目安)。原文タイトルが日本語ならそのまま、
  他言語なら内容に忠実に日本語化。タイトルの無いアイテム(X ポスト等)は
  本文から見出しを作る。誇張しない。
- summary: 200字以内の日本語要約(英語ソースも日本語で)。
- reason: なぜ私に価値があるか 1 文。implication: 「自分への示唆」を 1 文。
