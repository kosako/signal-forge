作成日: 2026-07-05 / 対象読者: 本人 / ステータス: ドラフト(v1 記録)

## 一行コンセプト

X・RSS・手動URLを毎朝10件以内の日本語ダイジェストに圧縮し、Telegramで受け取りObsidianに蓄積する、フルスクラッチだが徹底的に最小の個人インテリジェンス基盤。

## 背景と課題

情報収集の巡回(主にX)に約1時間/日を費やしており、さらに「後で読む」の未読負債が積み上がっている。解く痛みはこの2点: **巡回時間の圧縮**と**未読負債の解消**。見逃し防止は非目標(拾えなかった情報は諦める)。既製品調査の結論として、X取り込み+自由文の関心基準ランキング+意味論的ネガティブフィルタ+透明なフィードバックループを連結した製品は存在しないため、この核だけを自作する。RSS取得・要約・UIは既存部品(feedparser、LLM、Telegram/Obsidian)に寄せ、再発明しない。

## 成功条件とKPI

- **成功条件**: 運用2週間後、情報収集目的の巡回をダイジェスト(10〜15分)で代替できる日が週の過半。
- **KPI**: 毎日最大10件配信、うち3件以上が「読む価値あり」(Telegramの反応ボタンで測定)。
- 測定はフィードバック記録(🔖/✅/👎)を正とし、週次で集計する。

## スコープ

### やること

- X取り込み: 公式API従量課金。フォローグラフの逆時系列ホームタイムライン(owned reads $0.001/件)。リストAPI($0.005/件、5倍)は使わない。
- RSS取り込み: 生存フィード5〜10本。
- 手動URL投入: Telegram BotにURLを送る。
- LLM分析: 自由文の価値基準を注入したランキング+意味論的ネガティブフィルタ。
  - ↑: 今の課題に直結してすぐ解決 / ゲームチェンジャー級(Fable 5級)のキャッチアップ / 組織でのAI活用の実例・ROI測定
  - ↓: 細かいTips / 小粒な新製品ハイプ
- 出口2層: Telegram Bot(朝7時、最大10件、各アイテムに 🔖深掘り/✅既知/👎不要 ボタン)+ Obsidian Vault(アイテムノート・反応記録の蓄積層)。本文は日本語(英語ソースも日本語要約)。
- 運用: 常時稼働Mac mini、launchd + CLI(`intel collect / analyze / digest / run / doctor`)、ローカルファースト、Python + SQLite。

### やらないこと(MVP)

- 深掘り自動調査(🔖はフラグ記録まで。フェーズ2)
- フィードバックによるスコア自動調整(記録のみ)
- Webアプリ、Obsidianプラグイン、ベクトルDB/RAG、複数SNS対応
- 全文の無期限保存(抜粋+自作要約のみ恒久、全文キャッシュは期限付き)
- 見逃し防止のための網羅性追求

## システム概要

### パイプライン

```text
[X API] [RSS 5-10本] [Telegram URL投入]
     └──────┬──────┘
      collect(冪等・カーソル管理)
            ↓
      正規化・重複排除・本文抽出
            ↓
      analyze(LLM: 要約+価値基準ランキング+ネガティブフィルタ)
      ※ Codex CLI / claude -p ヘッドレス実行、API SDK差し替え可能な抽象層
            ↓
      digest(スコア順に最大10件、日本語)
            ↓
   ┌────────┴────────┐
[Telegram Bot 朝7時]   [Obsidian Vault]
 🔖/✅/👎 ボタン          Items/ + Daily/
            ↓
      signals(反応記録: SQLite→Obsidianにも反映)
```

### データモデル要約(SQLite正本、ObsidianはDBにしない)

- `sources`: 種別(x/rss/manual)、config、カーソル、成否時刻
- `items`: URL・タイトル・著者・published_at・content_hash・status
- `documents`: 抽出本文(期限付きキャッシュ)
- `analyses`: 要約、スコア群、推薦理由、モデル・プロンプトver・入力hash・推定コスト
- `signals`: 🔖/✅/👎、記録日時
- `digests`: 生成日、Markdown、item_ids

外部本文はuntrusted data扱い。LLMには分析のみさせ、スキーマ検証を通す。自動実行アクションは持たせない。

## 実装計画(2週構築+2週運用検証)

### Week 1: パイプライン骨格(RSSで一気通貫)

- リポジトリ・CLI雛形・SQLiteスキーマ・LLM抽象層(codex exec / claude -p ラッパ)
- RSSコネクター → 正規化・重複排除・本文抽出 → LLM分析(プロンプトver管理) → ランキング → Obsidian出力
- **マイルストーン M1**: `intel run` でRSSのみのダイジェストMarkdownが毎日生成される

### Week 2: X・Telegram・運用化

- Xコネクター(逆時系列ホームTL、owned reads、コスト計測)
- Telegram Bot: 朝7時配信+インラインボタン+URL投入受付、signals記録
- launchd登録、`intel doctor`、エラー通知(Telegramに失敗通知)
- **マイルストーン M2**: 全ソース+2出口が朝7時に自動で回る

### Week 3-4: 運用検証

- 毎日使い、KPI(3件以上価値あり/日)と巡回代替日数を週次集計
- プロンプト(価値基準の自由文)を手動チューニング
- **マイルストーン M3**: 2週間分の計測データで継続/ピボット判定

## コスト見積(月額、上限 $30)

| 項目 | 見積 |
|---|---|
| X API owned reads | $5〜15 |
| LLM分析 | $0(Codex/Claude サブスク枠ヘッドレス)。API併用時も数ドル想定 |
| Telegram Bot / RSS | $0 |
| インフラ(Mac mini 既存) | $0 |
| **合計** | **$5〜15(上限$30に対し余裕)** |

コストは `analyses.estimated_cost` とX APIの読み取り件数で常時計測し、`intel doctor` で月次見込みを表示する。

## リスクと対策(上位5)

1. **ダイジェストが「未読の置き換え」にしかならず読まなくなる**(最大リスク)
   - 対策: 件数上限10を厳守、推薦理由と「自分への示唆」を必須出力。発生時: 件数を5に絞りネガティブフィルタを強化。それでも週次KPI未達なら撤退条件へ。
2. **X APIの仕様・料金変更、逆時系列TLで拾える範囲が不十分**
   - 対策: 実装直前に料金・rate limit・取得範囲を公式で再確認。コスト超過アラートを doctor に実装。発生時: 追跡対象を厳選アカウントに縮小、またはX層を一時停止しRSS+手動URLで運用継続(パイプラインはソース非依存)。
3. **サブスク枠ヘッドレス実行(codex exec / claude -p)が不安定・規約変更**
   - 対策: LLM層を抽象化しAPI SDKへ1日で差し替え可能にしておく。発生時: API切替(コスト再見積、上限$30内で件数調整)。
4. **ランキング精度が出ず「読む価値あり」が3件未満**
   - 対策: 価値基準を自由文プロンプトで持ち、コード変更なしで毎日チューニング可能にする。signals を判定材料として週次でプロンプトに反映(手動)。発生時: 2週目にプロンプト集中改善スプリントを1回だけ実施。
5. **プロンプトインジェクション(外部本文がLLMへの指示として作用)**
   - 対策: 本文はdata扱いで分析専用、構造化出力をスキーマ検証、LLMに書き込み・送信権限を与えない。発生時: 該当ソースを隔離し、プロンプトの防御文言とパースの厳格化で対処。

## 撤退・ピボット条件

運用2週間(Week 4末)で判定する。

- **撤退**: 巡回代替できた日が週2日以下、かつプロンプト改善後も改善傾向なし → 開発停止。X APIコストだけ止め、学びをログに残す。
- **ピボット**: KPIは未達だが特定ソース/カテゴリでは価値が出ている → ソース構成・価値基準を組み替えて2週間再検証(1回まで)。
- **継続**: 成功条件達成 → フェーズ2へ。

## フェーズ2の展望

MVPで検証が通ったら、2つを検討する。(1) 🔖深掘りフラグをトリガーに、エージェントが背景・反応・一次情報を自動調査してObsidianに調査ノートを生成する深掘りパイプライン。(2) 蓄積したsignals(🔖/✅/👎)を使ったランキングの自動調整(フィードバックループの自動化)。いずれも本企画では設計せず、MVPのデータモデル(signals・analyses のメタ情報保存)が将来の入力として使える状態だけを担保する。
