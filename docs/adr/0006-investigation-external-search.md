# ADR 0006: 出来事の調査では、コードが外部の検索で材料を集めて LLM に渡す

- ステータス: Accepted(2026-11-14)/ 同日改訂: GDELT がこの回線からは 429 でほとんど断られたので、予備として Google ニュースの RSS の見出しを足した(ユーザーの判断)
- 関連: 設計 06 §4(深掘りの調査段の安全条件)・§9(出来事の調査)/ 設計 03 §3.5(今日の IT ニュース)/ GH#413 / GH#415

## 背景

- GH#413 で、朝のダイジェストの冒頭を「📰 今日の IT ニュース」にした。出来事の単位で、報じた記事のリンクを付ける。ユーザーの整理では、冒頭はその日のニュースのブリーフィング、下はタイムラインなどからの個別の記事、という二段の構成になる。
- 冒頭の件数は今ぐらい(4 件前後)がよい。一方で、もっと知りたいときに出来事ごとに「詳しく調査」したい、というフィードバックがあった(GH#415)。ユーザーは、代表の記事 1 本を今の深掘りで掘る案ではなく、出来事を報じた記事をまとめて調べる案を選んだ。さらに「報道をある程度広く調べ、X での反応もざっくり集めて返す」のがよいとした。
- 手元にある材料は、その日に集めた記事だけ(RSS 10 本と X)。同じ出来事の報道を広く読むには、外部の検索が要る。
- 深掘りの調査段(設計 06 §4)は「外部リサーチは v1 では持たない」としてきた。LLM にツールを持たせず、材料は DB の抽出本文だけを渡す。品質が足りなければ allowlist 付きの取得などを将来考える、としていた。

## 決定

1. **出来事の調査では、外部の検索で材料を足す。** 報道は GDELT の DOC API(公開・無料・キー不要。記事の URL が直接返る)で探し、本文は今の抽出の仕組みで取る。GDELT が断るか、使える報道が無いときは、予備として Google ニュースの RSS の検索(日本語版)で見出しと媒体名だけを拾う(本文は取らない)。X の反応は X API の直近の検索で読む(1 回 20 件。投稿者の情報 = expansions は取らない)。
2. **検索と取得はコード(orchestrator)が行い、LLM には道具を持たせない。** LLM がするのは、検索の語を作ることと、集めた材料を読んでまとめることだけ。検索の語は外へ出す前にコードが長さと文字を検査する。
3. **費用には上限を付ける。** この機能の月の上限は $5(X の読み取りの見積もり。UTC の暦月)。1 回分を足すと上限を超える月は X を読まず、報道だけで調べる(カードにその旨を出す)。費用は検索 1 回ごとに台帳(`investigation_x_reads`)に残し、全体の月 $30(doctor #9)にも数える。朝の収集の X の日次の読取上限とは別に数える。
4. **深掘り(記事 1 本が単位)の安全条件と台帳は変えない。** 外部の検索は出来事の調査に限る。深掘りの調査段は今までどおり外部リサーチを持たない。

Google ニュースの RSS は、はじめは使わないとした。記事への URL が Google の内部の符号で、本文を取るには非公式で壊れやすい手順が要るため。同じ日に実装して試すと、GDELT はこの回線から 8 回のうち 1 回しか通らなかった(5 秒に 1 回の制限に加え、429 の後の試し直しも数えて、10 分空けても 429 が続いた)。そこで GDELT には試し直さずに 1 回だけ送り、断られたら Google ニュースの見出しを使う。本文を取る手順(内部の符号を解く)は使わず、見出し・媒体名・記事への URL(押すとブラウザで記事に移る)だけを材料にする。

## なぜ / トレードオフ

- **却下: 手元の記事だけで調べる。** → 外部へは出ないが、RSS 10 本と X の範囲では「ある程度広く」に足りない。ユーザーの要望に応えない。
- **却下: LLM に Web の道具を持たせる。** → 接続サービスと Web のツールは GH#129 で外した。untrusted な本文を読んだ LLM が、自分で外へ取りに行く経路を作ることになる。何を取りに行くかをコードの側で決められない。
- **採用の利点**: 外へ出る通信の先(GDELT・X API・記事の host)と回数をコードが決める。LLM の出力が通信を直接起こさない。本文の取得は、記事の抽出と同じ SSRF の守りを通る。
- **代償(明示)**: GDELT は機械の収集で、当たり外れがある。この回線からは断られることが多い。予備の Google ニュースは非公式の口で、形が予告なく変わりうる(読めなければ報道の検索なしで続ける)。見出しだけの材料からは、見出しに書かれたことしか言えない。検索の語は外部由来の題から LLM が作るので、意図しない検索になりうる(読むだけで、費用は上限で止まる)。X の費用が増える。

## 安全条件

- HTTP は `app/http.py` の守りを通す。接続先の IP が global でなければ拒否し、リダイレクトのたびに検査し直す。受信量にも上限がある。
- 取った本文と投稿は untrusted data として、nonce のフェンスで囲んでプロンプトに渡す。中の指示には従わせない。
- 検索の語は 1 行に限り、長さの上限と、使ってよい文字の検査を通ったものだけを送る。X の検索の演算子は、コードが付けるもの(リツイートを除くなど)だけにする。
- 送信は orchestrator が owner の chat にだけ行う。接続は long polling のままで、受信ポートを開けない。書き込み先は vault の `SignalForge/DeepDive/` に限る(ADR 0004)。
