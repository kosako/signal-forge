# ADR 0003: 知見の単位は「深掘りの副産物」— AI ドラフト + ユーザーが結論確定

- ステータス: Accepted(2026-07-12)
- 関連: フェーズ2(B)/ ADR 0002(retrieval の主経路)/ `CONTEXT.md`(トリアージ / 深掘り / 知見)

## 背景・決定

retrieval(ADR 0002)の対象となる**知見をどう作るか**。知見の生成は二段階のファネルで起きる ── 第1段トリアージ(ざっと見て深掘り要否を判定・軽い・大量)、第2段深掘り(理解のため調べ裏付けを取る・重い・少数)。retrieval の価値の芯は第2段の産物にある。

決定: retrieval の単位(知見)= **深掘りした少数のものだけに残す「ソース + 調査/裏付け + ユーザーの結論(take)」**。記録は AI が深掘りの副産物として**ドラフト**し、ユーザーは**結論(take)だけを確定**する。深掘りの様式(自分でじっくり読む / AI に質問しながら)は問わず、記録は結論を要にして半自動で落ちる。トリアージ止まり(薄い印だけ)は知見に昇格しない。

## なぜ / トレードオフ

- **却下: 全記事に所感を書く。** → 雑務化して続かない。本プロジェクトが削ろうとしている「手間」を別の手間に付け替えるだけ(ADR 0001 の手動リスト却下と同じ論理)。
- **却下: ソースのみ、または AI 要約のみを貯める。** → 「なぜ価値があったか = ユーザーの結論」が消え、後から引いても使えない。エージェントの retrieval を毒する(ADR 0002 の精度要求に反する)。
- **採用の利点**: 記録コストを価値の芯(深掘り)にだけ集中させる。記録は深掘り作業の**副産物**なので追加の雑務にならない。ユーザーの結論を必須にすることで、retrieval の精度と主観の出所(なぜ自分に効いたか)を担保する。

## 未決(この ADR の射程外)

- 深掘りが起きる場所と知見の置き場 substrate(既存の Obsidian 蓄積か。ADR 0002 の MCP 対象と同一にするか)
- 記録の具体フォーマット(frontmatter・出典の持ち方)と、結論確定の UI/導線
