# ADR 0004: 深掘りは既存エージェント内 / 知見の substrate は Obsidian(専用 UI は延期)

- ステータス: Accepted(2026-07-12)。「専用 UI は延期」は ADR 0005(2026-10-18)で置き換え(操作するアプリは別プロジェクトの中央アプリで作る)
- 関連: フェーズ2(B)/ ADR 0002(retrieval の主経路)/ ADR 0003(知見 = 深掘りの副産物)/ H4(Obsidian vault)

## 背景・決定

深掘り(ADR 0003)が**どこで**起き、知見を**どこに**貯めるか。7/12 の構想では専用の読書 UI(訳・解説・原文並記)も候補だった。

決定: まず専用 UI を作らず、**深掘りは既存のエージェント(Claude Code / Codex / claude.ai)の中で行い、知見は MVP が既にダイジェストを書き出している Obsidian vault に貯める**(出力先は `[obsidian].vault_path` / `folder`。パス確定は宿題 H4 で、repo 既定は未設定=運用環境で設定する。設計 04 §7)。ダイジェスト(トリアージ層)とは**別の知見専用フォルダ**に書き、読みも書きも同一の知識ベースを MCP 経由で扱う(書き手 = 深掘りする agent、読み手 = 後の retrieval)。専用 UI は「この営みを深くやりたくなった / 量を増やしたくなった」時点まで**延期**する。

## なぜ / トレードオフ

- **却下(延期): 専用の深掘り/読書 UI を先に作る。** → 読む体験は作り込めるが、UI を 1 つ build/保守する。retrieval が北極星で読む体験は副次(「手を動かすもの」を低く置いた)ため、体験の作り込みより「書いて貯めて引ける」を最短で回す方を優先。
- **採用の利点**: (1) ADR 0002 のエージェント中心と一直線 ── 深掘り agent が書き手、別セッションが読み手、同一 MCP で閉じる (2) 新規 UI を作らず作る面が減る (3) substrate は MVP のダイジェスト出力先と同じ Obsidian vault(パス確定は宿題 H4・設計 04 §7)。リンク/グラフが「つながる」に効く。ダイジェスト(トリアージ層)とは別フォルダで知見層を持つ。
- **延期の条件を明示**: 量・深さが増して既存エージェント内では回しづらくなったら専用 UI を検討する。

これにより ADR 0002 / 0003 で未決だった substrate と深掘りの場が確定する。

## フェーズ2正本(PROPOSAL)との関係・安全条件

本 ADR は retrieval の体験・アーキテクチャを定めるもので、**PROPOSAL §フェーズ2境界を置換しない**。進出条件(🔖累計8件+50%深掘り)と段階化(まず「関連リンク収集のみ」の軽量版 → フルの調査エージェントはその次)は PROPOSAL が正。本 ADR の深掘り agent の書き込み経路は、PROPOSAL の**調査エージェント安全条件を継承する**: read-only 基本・書き込み先は Obsidian の知見専用フォルダに限定・送信/投稿/購入等の自動実行アクション禁止・untrusted 本文起点の実行はツール制限必須・接続は long polling(受信ポートを開けない)。

## 深掘りの要件: 英語コンテンツの日本語訳・解説(ユーザーフィードバック 2026-07-13)

初の実ダイジェスト確認で判明した実利用上の課題: 日本語記事は気になったら原文を見に行けるが、**英語記事は「中身を確認しに行く」障壁が高い**。ダイジェスト自体は英語アイテムにも日本語要約を付けているが、「要約より深く理解したい」時に言語の壁が残る。

→ 深掘り体験の**明示要件**とする: 深掘りは英語コンテンツに対し、**日本語での訳・解説・対話的な読み解き**を提供する(7/12 目指す体験の③)。これは本 ADR の「深掘りは既存エージェント内(訳・解説を agent が担う)」と一直線で、独立実装ではなく深掘り実装時の要件。なお日本語トレンドまとめ(GH#75)は英語障壁を**部分的に緩和**する(全体感を日本語で掴める)が、個別の英語記事を深く理解する部分は本要件が担う。
